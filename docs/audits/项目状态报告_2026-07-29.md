## 三、RAG 架构（当前状态）

### 3.1 数据流

```
归因 Agent → characters: [] (LLM不输出)
    ↓
extractCharactersFromUnits → 从 units speakerId+evidence 提取角色
    ↓ 建立 speakerId→canonicalName 映射
管线完成后 → RAG ingest (character chunks + scene patterns)
    ↓ chunkCharacterKnowledge 使用映射匹配 unit 文本
    ↓ 提取 appearance/relation/personality
RAG 存储 → rag-v2/characters.json (含嵌入向量)
    ↓
视觉提示词 Agent → 查询 RAG 获取角色外观历史
    ↓
AgnesImageProducer → 使用 entry.prompt (finalPrompt)
```

### 3.2 RAG 数据存储

- 路径：`{dataDir}/rag-v2/characters.json`
- 后端：`BaseCollection`（JSON 文件 + BM25 + 余弦相似度）
- 嵌入模型：`Xenova/bge-small-zh-v1.5`（512维，本地 CPU）
- 检索：Hybrid (BM25 40% + Vector 60%)

## 四、管线架构

### 4.1 两条管线并存

| 管线 | 入口 | 状态 |
|------|------|------|
| LangGraph 管线 | `packages/pipeline/src/graph.ts` | **主用**（API 路由调用） |
| Monolithic 管线 | `apps/api/src/orchestrator/chapter-pipeline.ts` | 备用/遗留 |

### 4.2 LangGraph 管线流程

```
narrative_parsing → attribution → rag_ingest_chars → segmentation
→ rag_ingest_scenes → vn_mapping → fidelity_review → visual_prompt → extract_assets
```

- `rag_ingest_chars` 和 `rag_ingest_scenes` 当前为空操作（避免修改共享 state）
- RAG ingest 在管线完成后统一执行（API 路由 `.then()` 回调）

### 4.3 Agent 列表

| Agent | 文件 | 功能 |
|-------|------|------|
| Narrative Parsing | `narrative-node.ts` | 章节文本 → 叙事单元 |
| Attribution | `attribution-node.ts` | 叙事单元 → 角色归因 |
| Scene Segmentation | `segmentation-node.ts` | 叙事单元 → 场景分割 |
| VN Mapping | `vn-mapping-node.ts` | 场景 → VN 脚本 |
| Fidelity Review | `fidelity-review-node.ts` | VN 脚本保真度审查 |
| Visual Prompt | `visual-prompt-node.ts` | 场景 → 视觉提示词 |

## 七、已知技术债

1. **场景分割不均** — 分割 Agent LLM 输出质量不稳定，第一个场景通常很稀疏
2. **归因 Agent 不输出 characters** — 依赖后处理提取，增加复杂度
3. **两条管线并存** — LangGraph 和 monolithic 管线逻辑重复
4. **ChromaDB 未启用** — rag 包支持 ChromaDB 但默认用 JSON 文件存储
5. **Consistency Review 未集成到管线** — 独立运行，不自动触发
6. **RAG v2 的 Narrative/Prompt 集合未使用** — 只用了 characters 和 scenes

> 以下问题已在 Phase 10 审计中修复：RAG 跨项目污染、管线失败状态管理、Ren'Py 导出崩溃、tasks 残留、SSE 状态闩死、前端数据截断、评测方向反转、LLM 截断不重试
